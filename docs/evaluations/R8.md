# R8 frozen evaluation evidence — 8 October 2026

The observed result is offline semantic retrieval on a small synthetic corpus.
It is not a live application, ingestion, answer-quality or permission benchmark.
This dated offline result is preserved. The later Docker/PostgreSQL and live Qwen
runs are recorded separately in [the October acceptance results](../EVAL-RESULTS.md).

| Held-out / English | 37 | 30 | 38 / 38 | 30 / 30; 30 / 30 | 0.983 |
| Held-out / Nepali | 3 | 3 | 3 / 3 | 3 / 3; 3 / 3 | 1.000 |

Each split has **41/41 required spans (Recall@8 = 1.0)** and **33/33 answerable
questions with full evidence**. The remaining seven questions per split comprise
five unanswerable and two access-denied cases. They have no permitted gold evidence
and are excluded from any/full-evidence and MRR denominators. Returning unrelated
passages on those questions is not a successful abstention.

An evidence group counts only when one of the first eight chunks fully covers its
gold block offsets, document and exact source version. Duplicates cannot increase
the numerator. Cross-document/conflict questions require both labelled groups.
Offsets are Unicode code points. This checks retrieved evidence coverage, not
the validity of a generated answer citation.

There were no Recall@8 misses in this run. `held-out-18` (curator onboarding lead)
had its first gold at rank 2, producing the English MRR reduction. This short corpus
is an easy, authored diagnostic; 100% recall does not establish general retrieval
quality. Only three Nepali questions per split were measured. Templates are separated
by topic/fact family, but this was not an independently authored blind benchmark.

## Reproduce without starting Docker

From the repository root, validate all file checksums and frozen labels:

```sh
uv run --project backend python backend/manage.py run_evaluations --suite r8-v1 --profile local-e5 --validate-only
```

With the local extra installed and E5 already explicitly prepared:

```sh
uv run --project backend --extra local python backend/manage.py run_evaluations --suite r8-v1 --profile local-e5 --embedding-only --split development
uv run --project backend --extra local python backend/manage.py run_evaluations --suite r8-v1 --profile local-e5 --embedding-only --split held-out
```

`--split all` reproduces the recorded combined run. Default split is development.
The command reads canonical fixture blocks, simulates permitted collections from
fixture personas **before ranking**, and uses no database, worker, Ollama, cloud key
or network model download. `pnpm models:prepare` remains the explicit download step
if artifacts are absent. `--embedding-only` is mandatory for inference; omitting it
fails instead of suggesting PostgreSQL/hybrid/generation was evaluated.

Keep new result files separately; do not silently overwrite the committed evidence
or regenerate the lock to make an altered suite pass. Change corpus/labels in a new
reviewed version, improve using development cases, then perform a new held-out run.
The owner diagnostics screen allowlists the two committed R4/R8 reports, validates
the R8 freeze and provenance, and recomputes its metrics before serving it. It shows
gold quotes and ranked retrieved chunks; no workspace documents enter these reports.
